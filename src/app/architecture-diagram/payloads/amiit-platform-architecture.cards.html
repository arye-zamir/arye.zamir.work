Product entry

  • • app.amiit.ai serves /{accountSlug}/chat and /{accountSlug}/manage as an installable PWA
  • • api.amiit.ai is the only backend door: no internal host ever appears in devtools
  • • Messaging adapters translate incoming requests into a shared channel.v1 contract

Amiit agent loop

  • • Amiit handles each request through an agent loop, drawing on Agentic Memory for context and calling tools through zaMCP
  • • The agent can work with tasks in Vikunja, knowledge in Forgejo, files in MinIO, and secure credentials in Bitwarden
  • • Redis holds durable state for the agent loop

Identity and trust

  • • iam-idp resolves the tenant from the token claim, RBAC/PEP default-deny; every service verifies bearer JWTs against its JWKS, fail-closed
  • • Vikunja and Forgejo web UIs sign in only through iam-idp OIDC, and the IDP admits admins alone; MinIO takes S3 credentials from the same IDP through STS web identity

Delivery and environments

  • • local dev → IP-gated staging → canary prod, all on one code path
  • • CI runs the gates already inside the Docker builds; iam-idp ships as a signed GHCR release image
